# Laboratory 02 – Build the Cloud Infrastructure Blueprint

## Mission Overview

This laboratory activity focuses on investigating the infrastructure components that support modern cloud computing. Using the KillerCoda Linux environment, cloud documentation, and GitHub, the activity explores compute, storage, networking, operating systems, and cloud provider services.

The goal of the mission is to understand how infrastructure components work together before deploying cloud services.

## Objectives

* Explain the major components of cloud infrastructure.
* Investigate hardware and software resources in a Linux environment.
* Differentiate compute, storage, networking, and identity resources.
* Understand the relationship between cloud infrastructure components.
* Compare AWS, Microsoft Azure, and Google Cloud services.
* Create a simple cloud infrastructure diagram.
* Produce professional technical documentation using Markdown.

## Cloud Infrastructure Components

The major infrastructure components investigated in this laboratory were:

* Compute resources
* Storage resources
* Networking resources
* Operating system
* Identity and access management

These components work together to provide the foundation for cloud-based applications and services.

## Linux Commands Executed

The following Linux commands were used during the investigation:

```bash
lsb_release -a
uname -r
lscpu
free -h
df -h
findmnt
hostname
hostname -I
ip addr
```

These commands were used to investigate the operating system, kernel, CPU, memory, storage, mounted file systems, hostname, and networking information.

## Skills Learned

During this laboratory activity, I learned how to inspect a Linux cloud environment using command-line tools. I also learned how compute, storage, networking, and operating systems work together in cloud infrastructure.

Another important skill developed was technical documentation using Markdown and organizing laboratory evidence inside a GitHub repository.

## Challenges Encountered

One challenge was understanding the different Linux commands used to retrieve system information. Another challenge was organizing the laboratory files and screenshots according to the required GitHub repository structure.

Creating the cloud infrastructure diagram also required careful planning to ensure that all required infrastructure components were represented clearly.
