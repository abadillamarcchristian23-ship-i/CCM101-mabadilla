# Laboratory 02 – Build the Cloud Infrastructure Blueprint

## Mission Overview

This laboratory activity focuses on investigating the infrastructure components that support modern cloud computing. Using the KillerCoda Linux environment, cloud documentation, and GitHub, the activity explores compute, storage, networking, operating systems, and cloud provider services.

The goal of the mission is to understand how infrastructure components work together before deploying cloud services.

## Objectives

* Explain the major components of cloud infrastructure.
* Investigate hardware and software resources in a Linux environment.
* Differentiate compute, storage, networking, and identity resources.
* Understand the relationship between cloud infrastructure components.
* Compare AWS, Microsoft Azure, and Google Cloud services.
* Create a simple cloud infrastructure diagram.
* Produce professional technical documentation using Markdown.

## Cloud Infrastructure Components

The major infrastructure components investigated in this laboratory were:

* Compute resources
* Storage resources
* Networking resources
* Operating system
* Identity and access management

These components work together to provide the foundation for cloud-based applications and services.

## Tools and Platforms Used

The laboratory utilized a combination of cloud-based environments, system administration tools, documentation platforms, and cloud provider references to complete the required tasks.

* **KillerCoda** – Served as the virtual Linux environment where cloud infrastructure concepts were explored and system-level activities were performed.
* **Linux Terminal** – Used to execute commands, inspect hardware and software resources, and gather system information from the cloud environment.
* **Draw.io** – Used to create a visual representation of the cloud infrastructure and show how the different components connect.
* **Markdown** – Used to structure, document, and present the laboratory outputs in a clear and organized format.
* **AWS Documentation** – Consulted to identify and understand Amazon Web Services infrastructure and cloud service equivalents.
* **Microsoft Azure Documentation** – Referenced to examine Azure's approach to computing, storage, networking, and other cloud resources.
* **Google Cloud Documentation** – Used to compare Google Cloud Platform services with the infrastructure components investigated in the laboratory.


## Linux Commands Executed

The following Linux commands were used to investigate the system resources and configuration of the Ubuntu cloud environment:

| Command | Purpose |
|---|---|
| `lsb_release -a` | Displays the Linux distribution name, version, release number, and codename. |
| `uname -r` | Displays the version of the Linux kernel currently running. |
| `lscpu` | Displays CPU information, including processor architecture, cores, threads, and model. |
| `free -h` | Displays total, used, and available RAM and swap memory in human-readable units. |
| `df -h` | Displays disk space usage and available storage for mounted file systems. |
| `findmnt` | Displays mounted file systems and their mount points. |
| `hostname` | Displays the name of the Linux server or virtual machine. |
| `hostname -I` | Displays the IP addresses assigned to the system. |
| `ip addr` | Displays network interfaces, IP addresses, MAC addresses, and interface status. |

These commands helped identify the operating system, kernel, CPU, memory, storage, file systems, hostname, and network configuration of the Linux cloud environment.
