
# Mission 3 Reflection

Completing Mission 3 gave me a better understanding of how cloud providers should be evaluated based on actual requirements instead of popularity. Among the three platforms, **Google Cloud impressed me the most**, particularly because of its strong connection to Artificial Intelligence, Machine Learning, data processing, and Kubernetes. I found its approach interesting because these technologies are becoming increasingly important in modern software development.

AWS, Azure, and Google Cloud have many similarities. All three provide virtual machines, object storage, databases, identity and access management, networking, monitoring, and security services. They also follow similar cloud concepts such as regions, scalability, resource management, and pay-for-use infrastructure. However, the way they name, organize, price, and integrate these services can be different.

I also learned that **business requirements strongly influence cloud platform selection**. For example, Azure makes more sense for a university that already depends on Windows Server, Microsoft 365, and Active Directory. On the other hand, Google Cloud can be a better fit for an AI research company because of its AI, data, and Kubernetes capabilities. AWS can be a practical choice for startups and global applications because of its broad selection of services and flexible architecture options.

Acting as a Cloud Solutions Consultant taught me that recommending technology requires more than memorizing service names. I need to understand the client's problem first, identify the technical requirements, consider scalability and cost, and then match those requirements with the appropriate cloud services.

My GitHub Cloud Computing Portfolio also improved after completing this mission. Instead of containing only laboratory outputs, it now includes organized research, comparisons, recommendations, Linux investigation results, screenshots, and reflections. This makes the repository more useful as evidence of what I learned and as a starting point for future cloud-related projects.

Overall, Mission 3 helped me think more like a cloud engineer because I learned to connect **business problems with technical cloud solutions**.
